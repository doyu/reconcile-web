# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A small **read-only FastHTML web viewer** over a `reconcile-archive` checkout (private repo with real financial data: one folder per month containing `statement.csv`, `statement.pdf`, `receipts/*.pdf`, `status.md`). It serves an accountant the monthly bank statement and receipts behind a single shared password. It **never mutates the archive** and runs **no LLM at request time** — all fuzzy matching was materialized into `status.md` offline by the collection skill.

Design spec: `docs/superpowers/specs/2026-07-02-reconcile-web-design.md` (includes the `status.md` contract). Implementation plan: `docs/superpowers/plans/`.

## nbdev workflow (critical)

This is an **nbdev** repo. Source of truth is `nbs/*.ipynb`; `reconcile_web/*.py` is **autogenerated — never edit it directly**. Follow the `nbdev-tdd` skill when editing.

```sh
source .venv/bin/activate          # project venv

nbdev-export                       # nbs/ → reconcile_web/
nbdev-test                         # run all notebook tests
nbdev-test --path nbs/00_archive.ipynb   # run one notebook's tests
nbdev-prepare                      # export + test + clean + README (run before committing)
```

Tests are inline `assert` cells in the notebooks, next to the exported cells they test, using a throwaway tmpdir archive fixture (`make_archive()`) that matches the `status.md` contract. CI (`.github/workflows/test.yaml`) runs the standard nbdev3-ci; docs deploy to GitHub Pages via quarto on push to main.

## Running the app

Config is env-only; `create_app` fails fast on anything missing:

```sh
ARCHIVE_DIR=~/reconcile-archive APP_PASSWORD=... SESSION_SECRET=... \
  uvicorn --factory reconcile_web.app:create_app
# or: python -c "from reconcile_web.app import serve; serve()"
```

HTTPS termination is the reverse proxy's job; deployment/CI-CD of the VM is out of scope for this repo.

## Architecture

Two notebooks → two modules, deliberately layered so the data layer could later be lifted into a skill/MCP:

- **`nbs/00_archive.ipynb` → `reconcile_web/archive.py`** — pure, UI-free data access over `ARCHIVE_DIR`: `list_months`, `month_counts` (tallies the status column of `status.md`, reads the `missing` count from its footer line — raises `ValueError` if the footer is absent, fail closed), `status_html` (Markdown → HTML), `safe_file` (resolves servable files).
- **`nbs/01_app.ipynb` → `reconcile_web/app.py`** — FastHTML routing + auth only: login/logout, month index, month view, authed file downloads. No parsing logic here.

## Security invariants (do not weaken)

Real financial data — these are load-bearing and each has a test:

- **Every route except `/login` sits behind the `Beforeware` auth gate.** Files are served only through authed routes, never statically; the `fast_app` default static route is removed right after app creation (its pdf/csv extension list would shadow the authed `.pdf`/`.csv` routes).
- **All file serving is contained to the resolved archive root** — two paths, same discipline: `safe_file` resolves single files (month must match `YYYY-MM`, receipt names are basename-only `.pdf`, symlink escapes caught by `resolve()` + `is_relative_to`); `month_zip` bundles a whole month and containment-checks **every enumerated entry**, not just files (`rglob` does not descend directory symlinks, so a files-only pass would silently drop an escaping one — fail closed, never a partial zip). Everything invalid raises `FileNotFoundError` (→ 404), never an error page with detail.
- **`status_html` treats `status.md` as untrusted**: raw HTML is escaped before rendering, receipt links are rewritten on the raw Markdown text, and a post-render pass strips any `href` not starting with `/m/` (Markdown `[x](javascript:…)` survives escaping; the allowlist closes it).
- Password check uses `secrets.compare_digest` on **bytes** (non-ASCII passwords).

## Conventions

- **YAGNI, ruthlessly** — the spec's Scope section is the whole app; Non-goals stay excluded.
- Determinism over cleverness in the request path: parsing is a few lines of regex/tally, not a general parser.
- Function signatures use nbdev docments style (one arg per line, `# comment` annotations).
